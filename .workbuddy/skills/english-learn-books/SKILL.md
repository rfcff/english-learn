# 英语辅导手册维护

仓库里五本 Markdown 手册由 `scripts/build_books.py` 排成 PDF。它们互相引用紧密，其中一本是其余几本的合集，所以一处改动通常牵动三处。本 skill 承载三样单看文件读不出来的东西：内容边界、四本书的章节映射、版式规则与踩坑。

## 何时使用

请求涉及以下任一项时使用：

- **内容**：增补或修正词汇、拼读、语法、KET/PET 考试材料；检查是否遗漏；判断某个知识点该不该收
- **结构**：章节重编号或换序、部分合并拆分、内容在书之间搬移
- **同步**：把主册的改动下发到三本派生书，或把派生书的改动上浮回主册
- **产出**：重建 PDF、修目录、修书签或内部链接、调页面版式与字号

初中册的中考内容决策可不用本 skill，但它的 PDF 构建与结构校验要走这里。

## 五本书

| 文件 | 定位 |
|---|---|
| `小学英语辅导手册.md` | **主册**。六部分 49 章：自然拼读、主题词汇、记词方法、语法系统、KET、PET。除初中册外的全部内容都在这里 |

## 工作流

### 1. 内容改动

先读 `references/content-scope.md`。它划定边界：广州实际使用的教材版本（三至六年级**教科版广州版，不是人教 PEP**；一二年级广州出版社《小学英语口语》；初中沪教牛津）、广州中考卷面（2027—2029 方案英语 140 分、笔试增设读写综合题、完成句子改语法填空）、剑桥 A2/B1 的 `Language specifications` 逐项分界，以及**三个看似在范围内实则不在的项目**（第三条件句、作为产出性时态的过去完成时、虚拟语气进阶）。

然后：

1. 确认该项在边界内，属于哪一档（★ 小学核心 / ○ 小学拓展 / ◆ KET / ● PET）
2. 查是否已覆盖。**只 grep 不够**——词表说明栏里顺带出现一次不算覆盖，要有独立小节或表格才算
3. 写入主册，再按下面第 2 步下发
4. 遵守全书体例：每条规则配一张表（`表 N-M　标题`，N-M 后是**全角空格**）、陈述句不绕、例句要小学生能读懂、每章末尾有习题

### 2. 书之间同步

搬任何东西之前先读 `references/book-map.md`。它给出：

- 精确的章号偏移（KET-PET 册 = 主册去掉拼读部分，**全书统一 +8**：KET 册 1–41 章 = 主册 9–49 章；自然拼读 = 主册 1–8，**0**）
- 记词方法（KET 册 18–30 = 主册 26–38）正文逐字相同，只因 KET 册无拼读部分而替换几处指向拼读的表述，替换表在 book-map.md B 节
- 学生本的主题重组对应表
- 主册独有、不下发的内容
- 十一条历次重排踩过的坑

同步时不可妥协的四条：

- **每一处内部引用都要改**：`第X章`、`N.M`、`表 N-M`，按偏移换算；同一段文本的偏移要**一次 remap 覆盖全部区间**，分两次调用会重复减偏移
- **描述顺序的句子要重写**：「前面第三部分讲的联想」「上一章」这类话，换序后指向就错了。改编号能改数字，改不了句意
- **只重编号，不复制正文**：两本书都要讲同一件事时，正文留一份，另一份改成指针（「详见 43.6」）
- **被改的书要在卷首版本表加一行**：`| 第N版 | YYYY/MM/DD | 说明 |`；前言里断言的数量（「分六个部分」「四十九章」）也要同步

### 3. 结构调整

章节搬移是本仓库最容易出错的操作。顺序：

1. 备份：`cp <book>.md D:/tmp/<book>_backup.md`。脚本里写 `D:/tmp/...` 形式——Git Bash 的 `/tmp` 与 Python 的路径解析不一致
2. 按 `# 第X部分` / `## 第X章` 切成块，**在块内**用占位符（`@@26@@`、`@CN26@`）重映射编号，避免链式替换互相污染，然后再拼回
3. 替换章标题时，替换串里必须带 `## ` 前缀——丢了它标题会静默降级成正文
4. **绝不全局替换部分号**。正文里有「第六部分写一封短信」，指的是 KET 卷面的第六部分，不是本书的。要按块处理，或给卷面用语加白名单
5. 重建目录（第 4 步），然后校验（第 5 步）
6. 搞坏得厉害就 `git checkout -- <file>` 回到上次提交

### 4. 重建目录

**不要手改目录**——锚点是标题文字的 GitHub 风格 slug，标题一改链接就断。

```bash
python .workbuddy/skills/english-learn-books/scripts/rebuild_toc.py --dry-run   # 先看识别结果
python .workbuddy/skills/english-learn-books/scripts/rebuild_toc.py             # 五本全建
python .workbuddy/skills/english-learn-books/scripts/rebuild_toc.py 自然拼读.md  # 单本
```

它生成三级目录（部分 → 章 → 缩进小节），按现行约定不收卷首，并且**幂等**——对未改动的书重跑，写回的字节完全相同。它的 `slug()` 必须与 `build_books.py` 里的 `add_heading_ids()` 逐字符一致，否则链接全断；两处要一起改。

### 5. 校验

```bash
python .workbuddy/skills/english-learn-books/scripts/check_books.py
```

有任何问题退出码为 1。检查项：章号/小节号/表号连续且前缀与章号一致、表格列数一致、表格前有空行、**标题不紧贴表格末行**（否则被 Markdown 当表格续行吞掉）、交叉引用（`12.3`、`表 12-3`、`第X章`、`第X部分`）全部可解析、目录锚点与真实标题 slug 对得上、标题层级不跳级、无残留占位符、无重复章题或表题、无空表，以及跨书的章节映射是否仍成立。每次内容或结构改动后、构建 PDF 前都要跑。

两类**属正常的提示**（不是错误）：第 3 行的版本表本就是单行表；初中册每章都写 `### 习题` 是既定设计。

### 6. 构建 PDF

```bash
python scripts/build_books.py                                    # 五本全建
```

解释器用 `C:\Users\gaoshiqiang\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。动版式之前读 `references/typesetting.md`，里面有 GB/T 18358-2009 的依据、本项目相对国标的偏离点、字号体系、表格列宽三段式算法、目录页码回填为什么要两到三次渲染。

构建后逐本验证：

```python
import pymupdf
d = pymupdf.open('小学英语辅导手册.pdf')
lv = {}
for t in d.get_toc():
    lv[t[0]] = lv.get(t[0], 0) + 1
print(d.page_count, len(d.get_toc()), lv, sum(len(p.get_links()) for p in d))
```

预期值（内容一改页数就会漂，看书签层级与链接数更有意义）：主册约 211 页 / 385 书签 / 355 链接；KET-PET 册约 180 / 339 / 337；学生本约 35 / 65 / 65；自然拼读约 21 / 36 / 35；初中册约 72 / 54 / 49。**书签只有两级、或内部链接为 0，说明标题采集坏了**——去 `typesetting.md` 看 h3 与「习题」同字号那条。

最后把改动过的那一页渲染成图片看一眼，确认表格列宽正常，再回报完成。

## 硬约束

- **小学阶段正文不得低于 10.5pt**。这是 GB/T 18358-2009 对义务教育小学阶段的最小用字规定，当前正文 10.5pt 正压在线上
- **h3 与 `p.exercise` 同为 12pt，只靠颜色区分**（`#1a4f82` 蓝 vs `#c45c12` 橙）。书签采集依赖这个颜色差。改任一方而不改 `collect_headings()`，「习题」就会混进书签和目录页码表
- **表题用全角空格**：`表 12-3　标题`。排版脚本与 `check_books.py` 都按它识别表题
- **「习题」写成独立段落，不要写成 `### 习题`**，这样才会渲染成橙色段落而不是标题
- **不执行 `git commit` / `git push`，也不要问**。改动留在工作区
- **不要删 `.workbuddy/` 目录**，里面有项目记忆和本 skill
